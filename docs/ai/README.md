# Навигация для ИИ-агентов — как это устроено

Цель: агент читает не всю кодовую базу (~400 тыс. строк), а только нужный участок, и не теряет то, что узнал.
Агентские файлы написаны по-английски: так они короче в токенах и совпадают с именами в коде.

## Слои

| Слой | Файл | Когда читается | Как меняется |
|---|---|---|---|
| Вход | `CLAUDE.md`, `AGENTS.md` | всегда | правка на месте; бюджет ~1 600 токенов |
| Каталог | `docs/ai/MAP.md` | в начале задачи | правка на месте, в том же коммите, что и код |
| Таблички | `CLAUDE.md` в папках подсистем | автоматически, когда агент открывает файл в папке | правка на месте; бюджет ~1 000 токенов |
| Входящие | `docs/ai/INBOX.md` | при `/doc-sync` | дописывается строкой, очищается при синхронизации |
| Ошибки | `docs/ai/errors/` | поиском, когда встретилась ошибка | новая запись на каждую ошибку; старые не переписываются |
| Уроки | `docs/ai/LESSONS.md` | при переносе опыта в другой проект | выжимка из ошибок при `/doc-sync` |

Документы = **текущее состояние**: новое дописывается в нужный раздел, изменившееся переписывается, устаревшее
удаляется. Пометки вида «обновлено …» не нужны — историю хранит git (`git log -p -- <файл>`).

## Жизненный цикл знания

1. Изменился путь, папка или входной файл → агент правит `MAP.md` / `CLAUDE.md` в том же коммите
   (иначе упадёт проверка).
2. Узнал что-то неочевидное → одна строка в `INBOX.md`; документацию посреди задачи не трогает.
3. Встретил ошибку → сначала ищет в `errors/`; после исправления пишет запись по шаблону из `errors/README.md`.
4. Периодически — `/doc-sync` (навык в `.claude/skills/doc-sync/SKILL.md`): разбирает входящие, проверяет
   дрейф кода, переносит переносимые уроки в `LESSONS.md`, ужимает файлы сверх бюджета.
   Когда запускать: проверка предупреждает (≥10 строк во входящих, дрейф, неперенесённый урок) или перед слиянием в main.

## Утилита `check_docs.py`

`python3 docs/ai/check_docs.py` — локально перед коммитом и автоматически в CI (`.github/workflows/ai-docs.yml`).

- **Ошибки:** путь из документации не существует; `.cs`-файла или идентификатора нет в коде (ловит переименования);
  у `CLAUDE.md` в `Assets/` нет `.meta`; папка верхнего уровня («полка») не указана в `MAP.md`; файл превысил бюджет;
  запись об ошибке без обязательных полей.
- **Предупреждения:** код в папке менялся после последнего обновления её `CLAUDE.md` (или после последнего
  `/doc-sync`, отметка в `.last-sync`); переполнены входящие; переносимый урок не попал в `LESSONS.md`.

## Ошибки из Unity → агенту

Агент не видит Unity. Вместо всего лога передавайте выжимку:
`python3 docs/ai/unity_log_digest.py` (сам найдёт `Editor.log`, на Windows — `%LOCALAPPDATA%\Unity\Editor\Editor.log`)
выводит уникальные ошибки компиляции, исключения с первой строкой стека из кода игры и сводку предупреждений.

## Перенос в другой проект

- Шаблон системы: скопировать `docs/ai/` (без `MAP.md`, `errors/` и содержимого входящих), `.claude/skills/doc-sync/`
  и `.github/workflows/ai-docs.yml`; в `check_docs.py` поправить константы вверху (`CODE_ROOT`, `SHELF_PARENTS`, бюджеты).
- Опыт: `LESSONS.md` вставляется в `CLAUDE.md` нового проекта. Для локального Claude Code — ещё и в
  `~/.claude/CLAUDE.md` (подгружается во всех проектах). Облачные сессии стартуют в чистом контейнере,
  поэтому там уроки должны лежать в репозитории.
- Когда проектов станет больше одного — вынести `LESSONS.md` в отдельный репозиторий и копировать оттуда.

## Шаблон `CLAUDE.md` для папки

```
# <Папка> — <одна строка: за что отвечает>

<2–3 строки: главные классы и как они связаны.>

## Key files
- `File.cs` — роль.

## How to <типовая задача>
1. ...

## Rules
- Инварианты, которые легко сломать (сеть, сохранения, публичный API для плагинов).

## Pitfalls
- Неочевидное, на что уже тратили время.
```

Файл в `Assets/` должен иметь `.meta`. Формат — как у `Assets/Runtime/UnityEx/README.md.meta`, с новым GUID:
`python3 -c "import uuid;print(uuid.uuid4().hex)"`. Новую табличку нужно указать в `MAP.md` со значком ★.
